# Sketch ProMax

<p align="center"><img src="assets/logo/sketch-promax-wordmark.png" alt="Sketch ProMax" width="420"></p>

An AI agent for Autodesk Revit 2024, 2025, 2026 and 2027, powered by Claude. Ask in plain language; it reads, documents, audits and edits the open model through 222 tools, and it learns new ones as you use it. Every change can be undone with Ctrl+Z, and it asks for your approval before anything risky (or before every change, if you prefer).

See [docs/PLAN.md](docs/PLAN.md) for the comparison with SketchPro, the roadmap and the architecture.

## How you use it

You chat in the **Claude desktop app**, next to Revit, on your normal Claude plan: no API key and no extra payment. The work happens in Revit. There is no chat inside Revit, because that would need a paid API key; your Claude plan can only be used through Anthropic's own apps.

The **Sketch ProMax** ribbon tab, by workflow (it sits right after SketchPro's tab):
- **Assistant**: **Chat** (Sketch ProMax inside Revit), then three large icons for the project: **Model checklist** (the pre-submission checklist), **Submissions status** and **Costing**; then **Update** (Update ready, Updated to the new version, Up to date with the time of the last check, Couldn't check; a click always checks now in a small window, never opens a browser), the running **Job** (click to stop it) and **Send view** (attach the active view to the chat), stacked.
- **Model**: small drop-downs stacked three high: **Structure** (columns, beams, slabs, slab edge cuts, raft, piles, walls), **Steel** (sections, bracing, connections, takeoff), **Reinforcement** (3D rebar and 2D detail drawings), **Marine** and **From architect** (link, arch to structure, copy and monitor).
- **Documents**: **Sheets & views**, **Tags & dimensions** and **Title blocks** (with revisions and clouds).
- **Check**: **Model check**, **Clashes**, **Drawing check**, **BOQ check** and **Purge & cleanup**.
- **Submit** (was Issue): **Submit check**, **Submit drawings**, **Redlines** (a marked-up PDF or photo applied, clouded, revised and exported; see below) and **Export** (PDF, list of drawings, quantities / BOQ, the project pack; see below).
- **My tools**: your saved recipes and learned tools, run right in Revit with no AI and no internet. It asks for any blanks ({level}...) and shows the result. Pin your most used tools, recipes and learned tools next to it as favourites (up to 12, in your order): click **Favourites**, or tick **Pin to My tools** in a tool's options window.
- **Sketch ProMax**: **Under development** (embodied carbon and value engineering: they work but are still being proven, so check their results), **Share tools**, **Settings**, **Help** (the guide, the desktop app connection, show or hide the pane, open the Claude app, the self-test and field test), **Report bug**, **License** and **Time saved**. When a newer version is out, a small notice at the bottom right of Revit (and a band at the top of the chat) says so, with Update now, What's new and Later; with automatic updates on it says "Updated to …" once the update is in. After the update to 0.35, restart Revit once so the new layout is in order.

Every Model, Documents, Check and Submit button runs its tool without the chat: a small options window built from the tool's inputs, with one short line on what it does, the model's levels and types as lists instead of typed names and ids, each field's help when you hover it, and the options nobody filled folded under More options. It remembers what you typed last time (`%APPDATA%\SketchProMax\tool-defaults.json`), then the tool runs as a job with a progress window you can stop. Its result shows as a page: the figures across the top, a bar chart of any breakdown, and lists whose rows open for their details and select their elements in Revit; the full text is under Full details, to copy for a bug report.

Several Revit windows, and different Revit versions, can be open at once. Name the model in chat ("in the Tower model, ...") and Claude switches to it.

If your company manages your Claude account, IT may need to allow the desktop app's local tools (MCP servers).

## Install

From a release: download `SketchProMax-<version>.zip` from [Releases](https://github.com/ahisham92/sketch-promax/releases), extract it and double-click **Install.cmd**. Or open PowerShell (Start menu, type PowerShell) and paste this line to install the latest release, no .cmd needed:

```powershell
irm https://raw.githubusercontent.com/ahisham92/sketch-promax/main/get.ps1 | iex
```

If Install.cmd says Windows cannot access the file: open the zip's Properties, tick **Unblock**, extract it again, or use the PowerShell line.

From source:

Requirements: Windows, Revit 2024 to 2027, and the .NET 8 and .NET 10 SDKs to build.

```powershell
.\build.ps1      # builds the add-in for 2024 to 2027 and the desktop-app connector into .\dist
.\install.ps1    # installs for your user, no admin needed
```

`install.ps1` copies the add-in into each installed Revit version, installs the connector to `%LOCALAPPDATA%\SketchProMax\mcp`, and registers it with the Claude desktop app, including the Microsoft Store version (your existing config is backed up to `claude_desktop_config.json.bak`). Revit repeats the registration at every start, so installing the Claude app later also works.

The chat inside Revit doesn't need the connector program: Revit serves the same tools to it directly, on this PC's own address (127.0.0.1, a new port and access token each time Revit starts), so it also works on company PCs that block programs which aren't signed (AppLocker, App Control). Only the Claude desktop app starts the connector. If that connection can't start, the chat falls back to the connector, and if the PC blocks the connector too, the chat says so and names the file to ask IT to allow.

Then:
1. Start Revit, choose **Always Load**, and open a model. The **Sketch ProMax** tab appears on the ribbon.
2. Restart the Claude desktop app. The Sketch ProMax tools show under the tools (plug) menu. Chat as normal: "Tag all doors in the active view".

Revit must be running with a model open for the tools to work.

**When Revit asks first** (Settings > Ask before changes, or the chat's model menu):
- **Ask only for risky changes** (the default): normal changes just run, each one Ctrl+Z (or the job card's Undo all) away.
- **Ask once per task**: the first change of a chat task asks once; the rest of that task runs.
- **Ask for every change**: a dialog before each change.
- **Always allow (never ask)**: nothing asks, risky changes included (the list below); only accepting or issuing past open issue check items still asks, since that is a QA sign-off. One click in the chat's model menu, or tick **Always allow** under any approval dialog's buttons. While it is on, **Always allow** shows next to the Brief pill by the message box.

At the first three levels Revit always asks before code Claude wrote (run_revit_code, run_revit_query_code), a recipe or learned tool whose steps are new on this PC, a delete that takes other elements with it, writing over an existing file outside `Documents\SketchProMax` and Sketch ProMax's own folders (new files never ask), value engineering applied to the open model, what-ifs, and accepting or issuing past open issue check items (the last of these at every level). Reads never ask. A brief you run (Brief before running) counts as approving its task, so its steps don't ask again except the risky ones. Each approval dialog says in one line what will change, with the details folded away, and offers **Allow the rest of this task** and **Don't ask again for** that tool (listed in Settings, where **Ask again** clears it).

**Chat animations** (Settings > Chat animations, applied straight away):
- **Full** (the default): the Sketch ProMax mark breathes while it works, new words of an answer fade in, each step shows a spinning ring and then a check or cross that pops in, Send and Stop morph into each other, your message rises from the box, and when a task of 20 seconds or more ends the answer glows once and Revit's taskbar button flashes if you are in another program.
- **Reduced**: only quick opens and closes (step details, the history drawer, hover fades) and the small progress spinners; the taskbar still flashes.
- **Off**: every change shows at once and the taskbar never flashes. With Windows' Show animations off, the chat behaves as Off whatever you pick.

**Parallel jobs** (in the Revit chat): the chat acts as coordinator. Ask for work with separate parts ("make sheets for levels 1-5 and check the walls") and it splits it into jobs, each its own hidden session with a card in the chat: its state (waiting to start, working, waiting its turn, done, stopped), what it is doing and, at the end, its report, which also goes back to the chat for a short wrap-up. **Open job** on a card (or the job's pill in the row above the conversation: Coordinator, Job 1, Job 2, each with its state) switches the pane to that job's own chat: everything it was asked and did, and the message box then talks to that job, attachments included. **Back to coordinator** (or Esc) returns to the main chat; **Stop** stops a job. A follow-up ("also add level 6") goes to the job it belongs to, not a new one. Reads run side by side; changes to the model take turns, one at a time. Up to 3 jobs run at once (Settings > Chat, 1 to 6), to keep within your plan's limits; jobs are saved with the chat. Jobs use the chat's connection inside Revit, so nothing extra needs installing (only if the chat had to fall back to the connector program does that need the same version as the add-in, which Install.cmd installs).

**Chat types**: each chat is **With coordinator** (it can hand work to parallel jobs) or a **Simple chat** (one chat does everything itself, step by step, with no jobs). The type shows under the chat's name and in the history; click it to switch while none of the chat's jobs is open. **New chat** starts your default type (Settings > Chat); the arrow beside it offers New chat with coordinator or New simple chat. Chats saved before types existed open as Simple chats, unless they already had jobs.

**Model and effort**: under the chat's name, **Model** and **Effort** start on **Automatic** (the Settings > Chat default). Automatic sorts each request, and each job, into simple work (rename, tag, list, fill parameters: Haiku, low effort), everyday work (sheets, views, dimensions, checks, normal modelling: Sonnet, medium) or hard reasoning (a spec or BEP against the model, redlines, tricky modelling logic, costing: Opus, high), and says in the chat what it picked when that changes; each job's card shows its model and effort. Pick a model or effort by hand and it sticks for that chat and its new jobs until you set it back to Automatic. Settings > Chat changes what each kind of work gets. Models are Claude Code's aliases, so each follows the latest version; effort uses Claude Code's --effort (low, medium, high, xhigh, max), and an older Claude Code without it runs at its default effort.

**Plan usage**: next to the model and effort pickers, the chat shows your plan's usage the way the Claude app does: "Usage: 5h 43%, 2h 10m left · Week 5%", the session counting down to its reset ("5h reset" once it has, until the next answer). Click it for each limit (the current 5-hour session, the weekly limit and, when one is in force, the weekly Opus or Sonnet limit) with % used and when it resets. The figures are only what Claude Code reports with each answer (its rate_limit_event), never estimated; the last report is kept until the next one. At 80 % of a limit the chat says so once, naming the jobs running then.

## Sharing tools (TritoRevit)

**Share tools** (next to the pre-submission checklist) packs any number of tools into one zip for colleagues, whether or not they have Sketch ProMax: the pre-submission checklist (colleagues start from the built-in checklist; tick **Include my checklist** to give them yours, and your later edits follow by themselves), issue check, purge & cleanup, project pack, time saved, ribbon tools that run without the AI, learned tools and recipes. Name the pack, tick the tools and, optionally, pick an update folder everyone can reach (a shared drive).

The colleague extracts the zip and double-clicks **Install TritoRevit.cmd** (no admin rights). When they don't have it, it installs **TritoRevit**, a small add-in with its own tab, downloading the add-in from this repository's releases (about 40 MB, once). Only that first install needs a Revit restart. With TritoRevit (or Sketch ProMax) already installed, a new pack's buttons appear on the TritoRevit tab within a few seconds, with Revit open.

Updates need no restart either: with an update folder set, Sketch ProMax republishes the pack there by itself when a tool in it changes, and every TritoRevit picks it up within a few minutes. TritoRevit updates its own engine from the same releases as Sketch ProMax and switches to it the next time Revit is idle. A learned tool or recipe a colleague already has under the same name, or edited after it arrived, is never overwritten, and a learned tool still asks once before its code runs. **Shared tools** on the TritoRevit tab lists the installed packs, adds one from a zip, checks for updates now and removes a pack. When both add-ins are installed, Sketch ProMax runs the TritoRevit tab's tools itself.

Problem reports come back to you: on a colleague's PC TritoRevit makes **Documents\TritoRevit - <pack name>** (for example TritoRevit - Pre Submission Checklist) with a **Bugs** folder and a short how-to. **Report a problem** (at the bottom of the checklist window, or in **Shared tools**) saves one small zip there with a picture of Revit, the versions, the pack revision and what failed; TritoRevit also saves one by itself when a shared tool fails. A copy goes to **Bug reports** in the pack's update folder when their PC can reach it, so you get it without asking; otherwise they send you the zip. Their checklist Word files and PDFs are saved in the same folder.

## License

Sketch ProMax works on the owner's PC and on PCs with a key made for them. On any other PC, **License** (Sketch ProMax tab) shows the PC's code, for example `SPM-7K2Q-9XW4-M3TD`; the user sends it to the owner, who sends back a key that works on that PC only (pasted on another PC it says the key belongs to another PC). Without a valid key the tools and the chat are off; updates, help, settings and bug reports still work. TritoRevit's shared tools need no key.

On the owner's PC the same button opens the **License manager**: make a key for a PC code with a name and an end date (or none), change a key's end date, cancel a key, and export the list to Excel. Keys are signed with the owner's signing secret, which is never in this repository; the add-in carries only the public half, so it can check keys but not make them. A later end date is simply a new key. An earlier date or a cancel reaches a PC that already has its key through `licenses/changes.txt` (key ids only), which licensed PCs read at each Revit start; the manager publishes it with the owner's GitHub token, added once.

The code is public, so this stops keys being passed around, not someone rebuilding the add-in without the check.

## Updates

Install once; after that Sketch ProMax updates itself, without restarting Revit. Each time Revit starts, and hourly while it is open, it checks this repository's latest GitHub Release. When there is a newer version a small window shows it downloading (percent and MB), verifying, unpacking and applying; you can hide it and keep working, or cancel the download. As soon as Revit is idle and no job is running, Sketch ProMax switches to the new version in place and says "Updated to X". The Claude app sees the new tool list straight away. Your settings are kept. Turn this off from **Settings**, or check right away with **Check now**.

How it works: Revit loads a small, never-changing loader (`SketchProMax.Loader.dll`) that owns the ribbon and loads the newest installed core (`SketchProMax.dll`) from `%LOCALAPPDATA%\SketchProMax\versions`. To switch, the loader stops the running core (its connection to Claude, its Revit event handlers and timers) and starts the new one, which takes over the same connection. The old DLLs stay loaded, unused, until Revit closes. Coming from 0.25.x, the first update still needs one Revit restart; from then on, none.

To publish an update: bump `<Version>` in both project files and push to `main`. The Release workflow builds on Windows and publishes `SketchProMax-<version>.zip` as a GitHub Release.

## What it can do

**Understand the model:** model summary, find elements by category/level/parameter, all parameters of an element, views and sheets, view templates, types, revisions, text notes, read any schedule, highlight elements.

**Documentation:**
- Tag any category in a view (doors, windows, rooms, equipment...)
- Dimension grids, walls, door/window openings and room clear widths; spot elevations placed automatically on every floor and roof in a view
- Create floor, ceiling and structural plans per level with templates and naming patterns
- Duplicate views
- Apply view templates
- Create full sheet sets in one go (including placeholder sheets) and place views on sheets
- Rename and renumber views, sheets, rooms, levels and types to firm standards
- Create schedules, then read them or export them to CSV/Excel
- Create revisions, add them to sheets, and cloud changed elements
- Translate drawings into any language (text notes, sheet, view, room and level names, schedule headings, type names, text parameters), or make them bilingual
- Sections (along a line or through elements), building elevations (N/S/E/W), interior elevations per room, callouts, 3D views with section boxes
- Visibility/graphics: hide, show or isolate categories and elements, color/halftone/transparency overrides, detail level, crop to elements, scope boxes
- Text notes, detail lines and filled regions in any view
- Align tags, turn leaders on/off, find overlapping tags and move them apart
- Format schedules: fields, headings, filters, sorting/grouping, itemize, totals
- Drawing list (sheet index) schedule, placed on a sheet
- Print to PDF (sheets go through the issue check first, from the chat as from the ribbon: nothing is exported while it has open items for them); export DWG, IFC, Navisworks NWC and PNG/JPG images

**Modeling:**
- Levels (with plans) and grids, including rectangular grid layouts
- Walls, floors and ceilings (from room boundaries or outlines), and flat, hip or gable roofs
- Doors and windows inserted into walls
- Structural columns at grid intersections and beams along grids
- Any loaded family (furniture, equipment, fixtures) placed with rotation
- Move, copy and rotate elements
- Stairs (straight, L-shaped or U-shaped with a landing) with railings, railings along any path, room separation lines
- Materials: create, color and assign (by parameter or by painting faces)
- Ducts, pipes, cable trays and conduits along a path, with elbows
- Curtain wall grid layouts at set spacings

**View filters:** create rule-based filters, apply them to views or templates with colors, halftone, transparency or hide, and color-code a view by any parameter in one step (e.g. doors by fire rating) with a legend.

**Pictures, sketches and cut sheets:** attach photos, PDFs, Word (.docx) and PowerPoint (.pptx) files in the chat or the desktop app. In the Revit chat a PDF is read whole, like the Claude app reads it, while the chat's PDFs and pictures stay within 18 MB and 100 pages; a larger one (a full drawing set or spec, 100 MB or more) is split by itself into parts that are each read whole by a helper chat: you keep asking in the one chat, it asks the parts that cover your question (all of them for a summary) and answers with the page numbers, and the steps show which parts it read. **Split PDF** in the pane's Activity tab makes such parts by hand, to attach or send on. Word and PowerPoint files give their text (headings, tables, slides in order) and their larger pictures.
- Build a Revit family from a product photo or manufacturer cut sheet
- Redraw a hand sketch as clean linework in a drafting view
- Place pictures or PDF pages into views and sheets

**CAD to Revit:** link a DWG, read its layers, and convert layers into walls (from double lines, with matching wall types), grids (auto-named), columns, floors, room separation or model lines.

**Location and coordinates:** read and set latitude/longitude, shared coordinates and true north; acquire coordinates from a link; convert survey points to model points.

**Mass placement:** place a family, group or linked model hundreds or thousands of times from a CSV/Excel list of points, levels, rotations and parameter values (survey coordinates supported).

**Several models:** list every connected Revit window and its open models, and switch between them by name, across Revit 2024 to 2027.

**Linked models and families:** list links and query elements inside them; load families from a file or by searching Revit's content library.

**Purge and cleanup** (Check > Purge & cleanup, or ask "purge this model"): every cleanup shows a preview first (counts by kind, the list, what else would go with it, the element count before and after; the preview deletes nothing, not even to undo it, and applying repeats the passes for what only becomes unused afterwards) and deletes only when you agree, as one Undo step. **Purge unused** is Revit's Purge Unused repeated until nothing new is unused (families, types, materials, appearance assets, line and fill patterns, group types, view templates and view filters no view uses), never the active view's template, anything a sheet uses or your title blocks, with a keep list for names never to purge. **Delete unused views** removes views on no sheet (legends, schedules and drafting views when asked) and keeps WORKING and _keep views, open views, the starting view, the last legend and views others depend on. **Clean up imports** removes imported CAD (or CAD links when asked), the types left behind and unused IMPORT- line styles and patterns. **Model health clean** removes unused view templates, unplaced rooms, areas and spaces, unplaced group types and unused filters, and lists Revit's warnings by type with a quick-fix hint. In a workshared model, elements another user has borrowed are left and named. Deleting views that hold annotation, or imports something is dimensioned to, asks first like any delete that takes other elements with it.

**Pre-submission checklist** (next to Chat): your office's checklist Excel walked through in stages (project details, one stage per section of the sheet, then review and sign). Each check shows how to check it, where it came from, its priority, any open point it waits on, and what the model says about it (file name, grids, worksets, warnings, imported CAD, title blocks, scales, links and more; read only). Answer Yes, No or N/A with a comment (keys Y, N, A), and the answers are kept per model. N/A removes the check from that model's checklist: it shrinks to one line with Put back, and leaves the score, the open list and the Word file and PDF (the checklist itself is unchanged). Review and sign lists what is still open, then writes a Word file or a PDF (made through Microsoft Word) to `Documents\Sketch ProMax\Checklists`, A4 landscape, ready to open or print. Signatures (your picture from Settings > Sign-off, another picture, or by hand) go in only when nothing is No or unanswered; otherwise the file says NOT READY. The office's checklist is built in, so no Excel file is needed. Edit the checklist… (on Project details) adds, changes, moves and deletes checks and stages and changes who signs; Export to Excel… and Import from Excel… edit it in Excel in the same layout. Edits are kept on your PC, answers stay with their checks when they are renumbered, and Use the built-in checklist goes back to it. Each check shows a short title; click it and the details panel on the right shows what the model found (the full list, such as every level not named to the standard), how to fix it, how to check it and the checklist's own wording. Show in Revit opens a view or Revit's dialog and moves the checklist to a narrow panel beside Revit so the view is in sight. Some checks have a Fix button (unload links, delete imported CAD or views on no sheet, ungroup groups used once, make the Navisworks view, set the landing view, put the office title block on every sheet, delete unused levels, move elements off Workset1 by category (Checking rules: Workset for each category) and make the missing worksets, hide linked models in views on sheets, fill empty view folder parameters, write the model name on the sheets, delete identical instances, save the submitted copy as _S03_R00 next to the model, and export the NWC, or the NWC only when the package needs no IFC; with Checking rules also set the project units, fill the UniFormat codes by category, name levels and scope boxes like the URS link, apply the view template for each view type, and rename types to the type name pattern from suggested names you can edit first): it asks first, and Ctrl+Z undoes it. Checks that need judgement (floating, duplicates, other trades' elements, clashes, including the clash report's) have Select these in Revit, which picks the elements found and zooms to them. Clear answer on a check takes its answer back, and Clear all answers (on Project details and Review and sign) takes them all back. Run this check, in a check's details, tests just that check after a fix. The two rings in the header are your answers and the automatic check; click the automatic one to see every check the model test fails. The automatic check counts all the checks: the ones the model can't test count only once you answer them Yes or N/A, so it can't reach 100% while they are left undone. For checks the model can't test, Ask Sketch ProMax to check hands the check to the chat, which looks at the model and answers PASS, FAIL or CAN'T TELL (Settings > Sign-off > Helper: Sketch ProMax; SketchPro, which opens SketchPro's Copilot and pastes the question for you to send; or none). Every check is marked Automatic or You check this, and Review and sign lists the ones you check yourself. Checking rules… (on Project details) sets what the automatic test compares with: file, level and scope box name patterns, the size limit, required and approved worksets, approved scales, the title block, the classification and IFC parameters, the sheet parameter with the model name, the view folder parameters, and more; they travel with the checklist's Excel file on its Rules sheet. NWC and IFC files don't record their export settings, so Sketch ProMax checks the ones it exported itself. The automatic tests also cover the submitted copy's name and the NWC and IFC file names (looked for next to the model), type names, other trades' elements, plans crowded with detail lines, types missing from the legends and schedules on no sheet. The title block check ignores the landing page's own title block and lists sheets that have none. Detail lines are tested on plans only by default, and views named like reinforcement or typical views are skipped (both set in Checking rules). Piles (types named like the piles rule, \*Pile\* by default) and columns that start below the lowest level aren't reported as floating. Slower ones run when you press Run the slow checks: duplicates and overlaps, floating beams and columns, clashes inside your trade, Sketch ProMax's model check score (standing in for the Model Checker template's), a comparison with your trade's standard template, and elements that overlap the same kind of element in a linked neighbouring model (joints and building edges). Point Checking rules at your files and more checks run on their own: the MIDP (4), the stage's drawing list (36), the Navisworks clash report (44), the signed checklist and Health Check report (46), the NWC and IFC (49 to 51; Fix it exports both with the office settings, named like the model) and the e-Transmit package (53 to 57; the slow checks open it from a clean folder). Every check in the Default has a model test now: free shapes (in-place families and DirectShapes, 16), sheets made from model views with no CAD on them (33), overlaps with neighbouring models (20, once they are linked) and what must be in the model (21, from Checking rules: What must be in the model; it doesn't replace a design review). Checklists with other wording get tests too when their checks read like these: the file name and its type field (RVT), the project's Revit version, the LOI matrix (the parameters each UniFormat code needs, iLOD, and in-place, Generic Model or DirectShape geometry, eLOD), piles modelled from cut-off to toe as one element with their parameters filled (piles modelled as structural columns take the cut-off and toe from their top and base levels and offsets, and the diameter from the type; the result shows the cut-off and toe range), and shared coordinates acquired from a linked CAD file. A checklist saved before an update picks up the new tests from its wording. Nothing is tested until you press Run checks; a strip under the header shows the progress, the check being read and a Stop button. Everyone starts with the same Default checklist, which arrives with Sketch ProMax updates; changing its checks asks for the password (0000 until it is changed), while your own Checking rules (your files and folders) never stop Default updates reaching you. Each project can have its own checklist (Settings, the gear: Checklist for this project): a new one starts as a copy of the Default for you to change freely (a ports checklist, say), or import one exported to Excel from another project. Your own checklists are kept on your PC for you only, and updates never overwrite them. Make this the Default for everyone saves the checklist shown as the next Default, to go out with the next update. Test before sharing (behind the same password) tests the checklist and Share tools in depth on a throwaway project (the Default, project checklists, your rules, Excel, Word and PDF, the password, reading a model, the windows, the Share tools zip and a colleague installing and following it) without changing your models, checklists or shared tools, and saves a report in `Documents\Sketch ProMax\Test reports`.

**Berth status** (next to the pre-submission checklist): for a project with several models and berths, each berth's status for its next submission as a percentage, made of modelling (against planned counts per category or type), categories and data (no Generic Models or in-place families, Assembly Code filled), services and openings (pipes, conduits, cable trays and ducts in the model and every loaded link, such as the electrical and telecom links, that pass through the berth's structure with no opening; open clashes in the Navisworks clash report when set; links not loaded), structural clashes (deeper than the clash tolerance, 50 mm by default, set on the setup's Week sheet), drawings (against the planned count, each with views and a title block), details, annotation (elements without tags, views without dimensions on the berth's sheets), schedules and bills, and deliverables (calculations, bills, back-up calculations of the bills, costing: typed by hand, or done when the file is in its folder). Each area's weight is yours, and any area can be set by hand with a comment. The overview shows each berth's percentage, next submission, working hours left and expected finish (from the pace of its readings, by hand, or Ask Sketch ProMax for an estimate) with On track, At risk, Behind or Overdue; click a berth for its areas, what to fix (Show opens the sheet or view, or selects the element) and comments, and export its Excel (Status, Submissions, Deliverables, one sheet per area with what to fix, Comments, History). A submission is due at 08:00 on its day by default and only working hours count (Sunday to Thursday, 08:00 to 17:00 by default). The project's models, berths (found by scope box, parameter, workset or the whole model; a documentation model can count its linked modelling models' elements), submission schedule, planned counts, deliverables, weights and working week come from one Excel file you keep (Setup: Make the setup Excel, then Import); change the schedule in that file and the tracker takes it the next time it opens. The model is read only when you press Update status, in short steps with a Stop button, so Revit stays usable; otherwise the window shows the last saved results. Everything stays on your PC in `%APPDATA%\SketchProMax\berth status`, and the Excel files go to `Documents\Sketch ProMax\Berth status`. Submitted packages keep being checked (Submitted, fixes open) so what the BIM submission still needs stays in view. The chat reads the tracker and records what you tell it (berth_status: "T3 sections designed 60%", calculations, bills, costing, comments, the expected finish); it never reads the model itself. Copy prompt moved from the ribbon to the pane (Claude app) to make room.

**Recipes and activity log:** save a workflow that worked as a recipe and rerun it later without the AI (with blanks like {level} filled in each time), on the open model or on a whole folder of models. Every tool call is logged per day in `%APPDATA%\SketchProMax\logs`, so Claude can report what it changed.

**Export for Claude:** Submit > Export > Project pack, or asking Claude to "export a project pack", writes one small zip to `Documents\SketchProMax\packs` named `<model> - Claude pack <date time>.zip` and opens the folder with it selected. Upload it to any Claude chat to prepare a report without Revit. It holds a README for Claude, project information, coordinates, levels and grids, element counts and quantities by category, type, material and level, Revit warnings, the sheet list with current revisions and issue status, views, revisions, up to 30 schedules (very large ones are skipped and listed), the newest saved check results (model check, clashes, drawing, rules, spec and BOQ checks, steel, rebar and precast schedules), change tracking, worksets, links, this model's in-Revit chat and any bug reports not sent yet. It is read-only, a few MB at most even on large models, has no images unless asked, and can be stopped from its progress window.

**Bug reports:** Report bug (Sketch ProMax panel or the pane), or telling Claude "that's a bug" in the Revit chat, saves one small zip to `Documents\Sketch ProMax\Bugs\Reports` with your one-line description, a picture of the Revit window, the versions, the model's name, the last 50 tool calls and the loaded-assemblies report. Nothing is sent. `Bug log.md` in that folder is this repository's [bug log](docs/bug-log.md), refreshed at every update check, with a "Not sent yet" list of your reports it doesn't have yet. Export chats puts the in-Revit chats of every model (last day, last week or everything), all bug reports, the tool-call log and the versions into one zip in `Documents\Sketch ProMax\Bugs\Exports`, to send to the developer.

**Brief before running:** before a request that changes the model (or takes several steps), the Revit chat first reads the model with read-only tools and shows a brief: the exact levels, types, views, sheets and counts in scope, the units, the tools it will use, every assumption, and one-tap choices for anything ambiguous. Nothing touches the model until you pick **Run this**, **Edit** (change the brief, then run it) or **Run as I typed**. When you edit a brief, the preference is kept as a "Brief preference" note (Notes tab), so later briefs need fewer edits; **Save to my prompts** keeps a brief you ran. Choose Always, Model changes only (the default) or Off under "Brief before running" in the model menu by Send; questions run at once.

**Notes Claude remembers:** say "remember that ..." in the Revit chat and Claude keeps it in `%APPDATA%\SketchProMax\memory.md`, for every model or for this model only; every chat starts with them. See, edit and delete them in the pane's Notes tab, or say "forget ...".

**Chats remember each other:** each chat keeps a short summary of itself (decisions, settings, steps that worked, what is left), written by a quick Claude run when you shrink it, leave it for another chat or leave it idle. A new chat about the same model starts with the latest three, so you don't explain the project again, and "do it the same way as in the Tower project" searches every chat of every model (the recall_chats tool) and follows that chat's steps. The summaries are in the Notes tab under "From earlier chats", to edit or delete.

**Excel, Word, PowerPoint and PDF files from the chat:** ask the Revit chat for a file ("make an Excel bill of quantities of the concrete with rates I can fill in", "a Word report of this model with a picture of level 1", "a 5-slide presentation for the client", "the same as a PDF") and it gets the facts from the model, then writes the file (the make_document tool). Excel workbooks have a bold, frozen header with filters, numbers as numbers, formulas for amounts and totals, and print fitted to the page width; Word documents and PDFs have headings, lists, tables, pictures and page numbers; presentations have a title slide, bullets, pictures and tables (long ones carry over). Nothing needs Office to be made. Files go to `Documents\Sketch ProMax\Made in chat` (or a folder you name) and never replace another file. Each one shows in the chat as a card with Open, Show in folder and Save a copy; exports such as the priced bill of quantities show the same card. PDFs use the standard PDF font, so for Arabic or other non-Latin text ask for a Word file and save it as PDF from Word.

**Shrink chat:** every message resends the whole conversation, so long chats use more of your plan. The arrows button next to New chat shrinks the chat: Claude Code replaces the earlier messages with a summary and carries on (the messages stay on screen). It also happens by itself after a reply once a chat sends about 60k tokens more than it did empty.

**Steps only you can do:** when a task hits something only you can do in Revit (a Revit API limit, a missing family or DWG, an edit mode, a legend component, a cut-edge dimension, a missing schedule), Sketch ProMax shows a window (or a card in the chat) saying what to do, where in Revit and why, with **Continue** (checks it is done and carries on where it stopped), **Skip this item** and **Stop**. Legend components are added by copying one that exists and changing its type (`add_legend_components`); cut-edge dimensions Revit refuses can be drawn as clearly labelled static stand-ins (`copy_dimensions` with `static_fallback`). Guides: [converting in-place families to loadable ones](docs/guides/in-place-to-loadable.md).

**Self-test:** the Self-test button on the Sketch ProMax tab (or asking Claude "test every tool on this model") runs each tool once on the open model, one at a time in the background, and reports pass, fail or skip. The quick check runs read-only tools only. The full check, meant for a copy of a model, also runs the editing tools and undoes each change straight after. Slow tools are skipped on large models, and the test stops if you switch to another model. The report is saved in `%APPDATA%\SketchProMax\self-test`.

**Field test:** Help > Diagnostics: field test builds a throwaway project, opens it in its own window, runs the tool families and the non-tool features against it, closes it without saving and writes one report (`%LOCALAPPDATA%\SketchProMax\field-tests`). By default it runs only what is new or changed: a step that passed in the last full field test in the same Revit year, and whose code has not changed since, is reported as **proven** with that run's date and version instead of being run again (the list is `src/SketchProMax/Data/field-test-proven.json`, made by `scripts/field-test-proven.py` from the full reports; "unchanged" is inferred file by file). Bug checks, new or changed tools and steps others depend on always run. Pick **Run everything** in the field test's question (or `run_field_test` with `full: true`) for a full run. Help > Test checklist lists the manual checks new or changed since that version first; the unchanged ones are listed apart. If Revit closes during a run, each step left a breadcrumb on disk first (`%LOCALAPPDATA%\SketchProMax\field-test`), so the next start writes a **field test (interrupted)** report of what ran, with the step that was running as a **crash** row (a failure), saves a bug report and says once which step it was; **Continue the field test after that step** (in that window or Field test's question, or `run_field_test` with `continue_after_crash: true`) builds the test project again, carries the earlier rows into the new report and doesn't run a step that closed Revit again, while Run everything still runs every step.

**Learns new tools:** when you ask for something no tool covers, Claude writes the Revit API code, and once it works it saves it as a new named tool with its own inputs. Learned tools show up as ordinary tools in every later chat and every Revit window, run behind the same approval, and are kept in `%APPDATA%\SketchProMax\learned-tools` (copy the files to share them). Ask "what have you learned?" to list them, or ask Claude to change or delete one.


**Openings and slabs:** find where pipes, ducts, cable trays and conduits (in this model or linked MEP models) cross walls, floors and beams, and add openings with your own opening family or a plain cut; cut notches or recesses into slab edges; add slab edges; lay out hollow core planks over a slab, room or outline with plank marks.
**Title blocks:** list title block types and which sheets use them, find sheets with no title block or two, fill title block fields on many sheets at once (with {number} and {name} placeholders, and Project Information), swap the title block type, add missing ones and move them to the origin. Make a title block family from a DWG, copy title blocks, legends, drafting details or schedules from another Revit file, edit the fixed text inside a title block family, create and bind shared parameters (and add them to the title block family), place a legend on many sheets, and add or remove a revision on many sheets.

**Exports:** DWG, IFC and NWC in internal, project base point or shared coordinates, DWG in mm, m or ft; one file per sheet named from a pattern such as '{number} - {name}', with a check that every file has exactly that name; the list of drawings (LOD) to Excel, checked against the exported files; a bill of quantities to Excel; schedule checks (empty cells, repeated marks, elements left out).

**Detailing:** keynote tags, detail components (point and line-based, e.g. break lines, insulation, blocking), dimension strings through any grids, levels, reference planes, walls or family instances in plans and sections, and toposolids from survey points or a site outline.

**Steel:** load steel sections from the content library by size (UB, UC, W, HSS, SHS, IPE, HEA...), place bracing in bays (X, diagonal, V, chevron), find joints and add steel connections (beam to column, beam to beam, base plates to footings or slabs, beam to concrete wall, brace gussets, column splices), and a steel tonnage takeoff to Excel.

**Reinforcement:** rebar in concrete beams (bottom, top and side bars, stirrups), columns (perimeter bars, ties), isolated footings (mats both ways) and area reinforcement on slabs, rafts and walls, with cover set; rebar cross and long sections with tags and a bar note placed on sheets, rebar in plan views, 3D rebar views through see-through concrete, and a bar bending schedule with tonnage to Excel. For offices that detail reinforcement in 2D, the same drawings can be made with the office's own detail families instead of 3D rebar: additional-bar lines across slabs (in named groups), a mesh symbol on each slab, and column section details in schedule cells, with the family names remembered per model and every family parameter written and read back (rft_detail_families lists the families and their parameters).

**Precast and post-tensioning:** precast slab layouts (hollow core, solid planks, filigree planks, double tees) with joints, cut units and an optional structural topping, a precast unit schedule with lifting weights, post-tensioning tendons in slabs (along lines, uniform or banded on column lines) and beams with a parabolic drape over the supports, and a tendon schedule with strand quantities.

**From architecture to issued drawings:** turn the architectural model into a structural one (load-bearing walls, columns sized from the architect's, structural slabs), ramps as sloped slabs with landings and a gradient check, housekeeping pads under MEP equipment, a sleeve and opening schedule, general notes from a structural template, typical detail tables (laps, covers, hooks), and one-step issue: revision, checks, PDF and DWG per sheet with your naming, and a checked list of drawings.

**Model health and change tracking:** a scored model check (Revit warnings by type, duplicates, wall gaps, beams on nothing, columns off grid intersections, elements slightly off-axis or far from their level, unplaced or unenclosed rooms, empty required parameters), missing items (rooms with no door, columns with no footing, masonry openings with no lintel, untagged structure, empty sheets, architecture with no structure), model and link snapshots compared for added, deleted and modified elements with coloured views, and coordination progress over time (new, resolved and open clashes per test), all to CSV with optional BCF.

**Quantities, cost and documents:** check a hand-made BOQ (Excel, CSV, or rows read from a PDF) item by item against the model with differences flagged, find double-counted concrete where elements overlap without joining, show the basis of calculation for any item (elements, dimensions, formula, deductions, waste, NRM2/POMI/CESMM4 void rules) and select its elements, estimate cost from your rate table and compare with the last estimate, and check requirements from specifications, minutes, the basis of design or design reports against the model and the drawing notes.

**Embodied carbon:** assess the model's embodied carbon following EN 15978 and the RICS whole life carbon conventions: modules A1-A3 by default, with optional A4 transport (distance and mode) and A5 site waste. Quantities come from the model's material volumes: concrete by strength class (C32/40, 40MPa...) and cement replacement, reinforcement from modelled bars or an assumed kg/m³ per category that you can change, structural steel, timber, masonry, glass, aluminium and others, optionally in linked models. You get the total tCO2e and kgCO2e/m² (from a gross area plan, the slab areas, or the GIA you give), breakdowns by material class, level, category, type and material, the top contributors, the materials no factor covers (listed, never dropped), and an assumptions section, in Excel and CSV. The built-in factor table (`src/SketchProMax/Data/carbon-factors.csv`, versioned) holds generic placeholder values with their sources (ICE v3.0 as tabulated by IStructE, RICS defaults) that must be checked before reporting; give your own table (CSV or Excel: material pattern, class, unit, kgCO2e per unit, stage, source) and it is remembered for the model. Compare two options or snapshots (for example GGBS instead of CEM I, or C32/40 instead of C40/50) to show the saving, and colour the model by carbon intensity in a new 3D view.

**Value engineering (screening aids, not design; an engineer confirms every item):** ve_opportunities ranks where cost or material could be saved, with an estimated cost and carbon saving, a confidence and the element ids: slabs, beams and walls thicker than typical span/depth ratios, many slightly different sizes that could become one (suggested groups), the concrete grade mix and grades above typical, modelled reinforcement above typical kg/m³, steel kg/m², formwork complexity per level, and over-specification against a spec. The rules of thumb are listed in every report and can be replaced; costs come from cost_estimate's rate table (generic placeholder rates otherwise) and carbon from the embodied carbon factors. ve_compare_options sets RC flat slab, beam and slab, PT, precast hollow-core, steel composite, raft and piles side by side for a grid, span and load (quantities, cost, carbon, a rough programme index, risks), sized by documented rules of thumb or measured from the model or a design option. ve_view colours the ranked items in a new 3D view; ve_apply tries a change (switch types, rationalise sizes, change the concrete grade) on a saved copy (for a workshared model: run it in a detached copy, or use a design option) or in a design option, with before and after cost and carbon; ve_register keeps the VE register per model (ids, status proposed/accepted/rejected, owner) and exports it to Excel and CSV.

**Redlines in, revised sheets out:** give a marked-up PDF or a phone photo of markups. redline_read shows Claude a page as an image (a PDF page is rasterised by Revit itself, so no PDF reader is needed) and Claude reads each markup (text, clouds, arrows, strike-throughs, dimension changes) with its place on the sheet. redline_plan matches each one to its sheet (the title block number read, or sheet_number), the viewport and view it falls in, and the element it means, and lists the planned changes. redline_apply applies them (it asks you to approve each change one by one when you ask for that, or when Settings asks for every change; a strike-through that would delete other elements with it is always asked) (text and notes, parameter values, dimension overrides, element moves where a dimension change is explicit, deletes for strike-throughs), draws a revision cloud round each on the sheet under one new revision, exports the revised sheets to PDF, hands what it couldn't interpret to you as manual steps, and writes a done / not done report to Excel and the chat. From the ribbon (Submit > Redlines) the pages are read by Claude Code on your Claude plan, as a job outside Revit: Revit stays usable while it reads, the Job button shows the page it is on and stops it, and the approvals and the result come up when every page is read. A photo's markups are placed as fractions of the sheet in the photo (no perspective correction), so check its matches in the list.

**Analysis:** check the analytical model (free ends, gaps, short members, missing analytical or physical elements) and export it to SAP2000 (.s2k) with sections, shells, materials and supports, plus CSV tables.

**A drawing package from one sentence:** "GA plans, sections and column schedule for levels 1-5 on A1 with our title block" becomes a plan with counts (views, sheets and their numbers, title block, tags, grid dimensions), which Claude shows you, and Revit too when Settings asks before changes, then one checked pipeline: views, dimensions, tags, sheets with title blocks, title block fields and a drawing register or transmittal sheet with an Excel copy. Each stage is checked (views exist, every view placed, nothing overlaps on a sheet, no orphan tags, then the drawing checker), Pause, Skip step (skips a stage) and Stop work on the job card, and it ends with a time-saved line. The whole package is one Undo step and never changes or deletes your existing views or sheets; a missing title block or tag family, or a view too big for its sheet, is handed to you to fix.

**One prompt to an issued package:** link the architectural model (link_model), build the structure from it with door and window openings, add a raft a set depth under the slab on grade (create_raft), make GA plans with sheets, tags and dimensions, reinforce rafts, slabs, beams and columns with typical values marked ASSUMED, and issue the set "Issued for Construction" (revision, checks, PDF/DWG, list of drawings). work_progress saves the plan and each step's result with the model, so a long job picks up where it stopped after "continue".

**Marine, infrastructure and robustness:** piles (round, square or tubular, vertical or raked, at points, on a grid or in rows along an alignment), revetments and rubble breakwaters with armour, underlayer and filter layers, crown walls, gravity block quay walls, cantilever retaining walls, masonry walls, gravity dams, open-piled jetties and quay decks, bridges (deck, piers, abutments), floating pontoons, manholes, planters and hoppers; bollards, fenders, ladders, cleats and crane rails along a quay edge; design vessels (tug to ULCV, hopper barge and dredger) at a berth; vessel impact screening (PIANC berthing energy, AASHTO collision force, exposed piles and piers); and progressive collapse screening (notional column removal, transfer columns, tie forces).

**Coordination:** write issues (elements, snapshot and camera) to a BCF file for ACC, Navisworks, Solibri or BIMcollab. Clash detection between trades and linked models (hard and clearance clashes, CSV and BCF), a drawing checker (grids and levels against links, overridden dimensions, duplicate marks, sections not on sheets, empty sheets, missing title block fields), code and standards rules checks from your own rule packs, construction sequence numbering with step-by-step 3D views, copy/monitor of levels, grids and columns from links, and loading plans (live and superimposed dead loads per room) from the architectural link.

**Anything else:** Claude can write and run short Revit API code (C#) for what no dedicated tool covers, such as stairs, railings, materials, curtain walls or MEP. Read-only code runs freely; code that changes the model is shown to you first and is one Undo step.

**Model data:** set parameters in bulk, place rooms automatically, duplicate types with new values, swap types, manage worksets, delete elements.

**QA:** deterministic model audit (unplaced/unbounded/unnumbered rooms, duplicate room numbers, untagged doors and windows, views not on sheets, empty sheets) and visual review of rendered views and sheets.

**Firm standards:** write your conventions in plain English in Settings (naming, numbering, tag styles). Claude reads them at the start of every conversation.

## Adding a tool

1. Implement `IRevitTool` (name, description, JSON schema, `ModifiesModel`, `Execute`).
2. Wrap model changes in `RevitHelpers.StartTransaction(doc, "...")` and `Commit()`.
3. Return `ToolResult.Ok(new { ... })` with counts and element ids so Claude can verify its work.
4. Register it in `ToolRegistry.CreateDefault()`. It appears in the desktop app the next time Revit and the app start.

## Status

The add-in compiles for Revit 2024 to 2027, and the desktop-app connector has been tested end to end against a simulated Revit. It has not been run inside a real Revit session yet, so expect small fixes on first launch.
