Long unattended runs no longer get stuck after Sketch ProMax updates itself while a call waits.

- If a call was cut off while Sketch ProMax switched to an update, Revit stayed "busy" with it and refused every later call, even after cancel_job. Now that call ends with an error, and simply sending it again works (bug 87, please check).
- A call dropped by cancel_job before it started never blocks the next one. A call still waiting when Sketch ProMax switches to an update is told why.
